## 开始

识别交付模式：

- 普通 `grill`：先问拷打强度，以及要不要留决策记录（decision log）。用户已说明的不再问。
- `grill-with-docs`：用户输入 `/想清楚`，或明确要求该模式、要求追问结束形成文档时使用。先问拷打强度；文档是此模式的最终交付，不再问要不要留记录。用户指定了文档类型、位置或格式时遵从；否则默认生成 Markdown。

强度分为：

1. 浅问：只补最关键的缺口
2. 常规：把明显没想清楚的地方问明白
3. 细问：检查目标、约束、取舍和默认假设
4. 深挖：主动寻找风险、遗漏和边界情况
5. 拷打：严格挑战前提，直到重要未知基本暴露

用户可以随时调整强度。

## 分轮追问

每轮只询问当前已经具备前提的问题；依赖尚未确定答案的问题留到下一轮。优先追问会明显影响后续方案的内容：真正想解决的问题、已确定与未决定的事项、默认前提、遗漏，以及改变方向的取舍。

能自己查清楚的事实不要交给用户；涉及用户的目标、偏好、成本和取舍时，再让用户决定。必要时提供选项和建议，但不要替用户决定。

每个问题使用：

```
❓ Q1｜问题标题
问题内容。需要时给出选项。
➡️ 建议：简短给出你的推荐和理由。
```

同一轮有多个问题时继续 Q2、Q3。问题保持具体、容易回答。强度决定追问深度，不只是问题数量：浅问处理关键缺口；常规补齐明显缺口；细问检查隐含假设和取舍；深挖寻找边界情况；拷打挑战模糊回答、未经验证的前提和互相冲突的要求。

不要为了「拷打」而无限追问。当剩余未知不足以明显改变下一步时停止。

## 记录与交付

普通 `grill` 选择留记录时，每定一条就追加「结论 + 理由」，另列待定问题。能写文件就在当前项目新建 `docs/decisions-<英文主题>.md`；不能写文件则每隔几轮贴出完整版供复制。结束时简短总结已确定、暂未确定、下一步，等待用户确认后再开始重要执行。

`grill-with-docs` 在追问收束后形成完整文档：

1. 根据实际对话整理目标与背景、关键结论及理由、方案或行动步骤、重要取舍、风险与假设、待定问题和下一步。只保留相关章节；清楚区分用户已确认的决定、事实、推断和建议，不把未确认的建议写成决定。
2. 若工作区可写，按用户指定位置保存；未指定时保存在当前项目的 `docs/<英文主题>.md`。文件名简洁且不覆盖已有文件；已有同主题文档需要更新时，先阅读再整合。若无可写项目或用户只需要聊天内容，在对话中给出可直接复制的完整 Markdown 文档。
3. 写入后核对文档是否覆盖关键结论、理由和待定事项，向用户给出文档位置及简短摘要。文档交付不等于执行其中的方案；后续重要执行仍等用户确认。
